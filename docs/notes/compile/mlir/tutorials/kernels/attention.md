# Attention 的计算与中间存储

Matmul 说明一个输出块怎样积累多个归约块的贡献；Softmax 说明一行分数怎样变成归一化权重。Attention 把这两种计算接起来：先比较 query 与 key，再用得到的权重合并 value。

本章先建立一个能完整核对的基线，追踪中间矩阵的含义和生命周期。下一章再改变计算组织，使权重不必完整保存。没有这个基线，就很难判断后来的融合究竟省掉了什么。

## 1. 三份输入与两次矩阵乘法

先只看一个 batch、一个 head。Q 的形状为 M×D，K 为 N×D，V 为 N×P：

```text
S = scale * Q * transpose(K)     形状 M×N
W = softmax(S, along keys)       形状 M×N
O = W * V                       形状 M×P
```

Q 的一行是一个 query，K 的一行是一个 key；S[i,j] 是第 i 个 query 与第 j 个 key 的分数。W[i,j] 是合并 V 的第 j 行时使用的权重。P 可以与 D 不同。

常见的 scale 为 `1/sqrt(D)`，它是算法的一部分，不是编译器可以随意省掉的常数。这里不包含 dropout、额外 bias 或反向传播；这些扩展要分别增加语义和状态。

## 2. 沿一行追踪最终输出

设某个 query 的四个分数是 `[0,0,0,ln(2)]`，相应标量 value 为 `[10,20,30,40]`。稳定 Softmax 先减去最大值 ln(2)，得到指数权重 `[1/2,1/2,1/2,1]`，其和为 5/2。

归一化权重为 `[1/5,1/5,1/5,2/5]`，最终：

```text
O = (10 + 20 + 30 + 2*40) / 5 = 28
```

最终需要的是这个加权结果，不一定需要把所有 W 留给调用者。这为后续融合提供机会。但加权时使用的分母来自整行，不能只看到前三个 key 就把它们当成最终概率。

## 3. 在结构化 IR 中表达计算

QKᵀ 可以使用 Linalg 的访问映射表达，不要求先实际复制一份转置后的 K。它的迭代维为 (i,j,h)：

```text
Q: (i,j,h) -> (i,h)
K: (i,j,h) -> (j,h)
S: (i,j,h) -> (i,j)
iterator_types = [parallel, parallel, reduction]
标量区域：acc + q*k
```

这里 h 是归约维，j 是 key 的编号。后面的 WV 则使用 (i,p,j)，沿 j 归约。这两个 matmul 的归约维不同，不能只因都含 j 就把循环直接拼接。

中间 Softmax 由沿 key 的 max、exp、sum 和 normalize 组成，正是[已有 Softmax 章节](./reduction_softmax)中的过程。可以继续保留 Tensor/Linalg，直到选定调度与存储；也可以为观察基线显式写出 SCF 与 MemRef。

配套基线采用后一种方式。每行先计算并保存分数，随后把这份存储原地改写成减最大值后的指数权重，最后形成加权和并除以分母。它避免再分配第二份 M×N 矩阵，但仍保留一份这样的中间存储。

## 4. 中间矩阵的生命周期

基线的存储过程为：

```text
scores[i,j] = Q[i,:] · K[j,:] * scale
    ↓ 求整行最大值
scores[i,j] = exp(scores[i,j] - max_i)
    ↓ 求分母，形成与 V 的加权和
O[i,p] = weighted_sum[i,p] / denominator_i
    ↓
scores 可以释放
```

对全有效、M=N=L 的 f32 输入，仅这份 scores 就占 `4*L*L` 字节。L=4096 时约 64 MiB，L=16384 时约 1 GiB；还未计算 Q/K/V/O、其他 head、batch 或训练保存的状态。

这些数字是分配大小，不能直接当作一次 kernel 的 DRAM 流量。真实读写还取决于实现、缓存、融合和重计算。但二次规模的中间矩阵已经足以解释为什么只优化两端 matmul 可能解决不了整体问题。

## 5. Mask 的作用位置

一个 query 未必允许访问所有 key。数学上常把无效分数写成负无穷，使其指数权重为零；实现也可以跳过无效位置，直接确保它不参与 max、sum 和加权和。

实验选择容易核对的前缀 mask：第 i 行只允许 `0 <= j < lengths[i]`，且调用者保证 `0 <= lengths[i] <= N`。例如 causal 情形可选择 `min(i+1,N)`。它能演示长度和因果边界，不宣称覆盖任意稀疏 mask 的表示。

若一行完全无效，直接计算 `-inf - (-inf)` 会产生 NaN，随后归一化也没有非零分母。因此实现必须先约定这种输入的结果。本例将空有效集合扩展为全零输出，并显式绕过除法；具体前端是否采用相同约定，应另行确认。

尾部屏蔽解决越界，算法 mask 解决哪些 key 有资格参与，二者不能混为一谈。即使某个地址在分配范围内，也可能被 causal mask 禁止。

## 6. 数值和输入契约

本例使用 f32 乘加、指数与输出，double 计算作为测试参考。输入、scale 以及生成的分数要求有限；标准 scale 还要求 D>0。测试包含正的大分数和多块归约，但没有为 NaN、无穷值、任意溢出或低精度累加定义新的语义。

稳定 Softmax 防止直接对很大的分数求 exp，并不保证 QK 点积本身不会溢出。矩阵指令的精度模式、累加精度、指数近似与归约重排都会影响误差，需要在所选目标上继续检查。

参考结果除了逐元素误差，还应覆盖不同长度、最后不足一块、单 key、完全屏蔽行与空 batch。只比较两个经过类似变换的实现，可能让同一个错误同时存在；独立的数学参考因此有价值。

## 7. 从完整矩阵到在线状态

当前基线中，scores 用完即可释放，且调用者只需要 O。希望继续省内存，就要回答：读过一部分 key 后，保留哪些信息，才能在后续看到更大的分数时仍正确更新结果？

下一章[在线 Softmax 与分块 Attention](./online_attention)会推导一个最大值、一个归一化总量和一组加权累加器怎样替代完整中间行，并把它写成真实 MLIR 循环。

阅读时可以先检查三点：S/W 的两个维度分别指谁；为什么归一化分母跨越全部有效 key；全 mask 行为何必须由接口明确约定。完整可运行输入与 C 参考位于 [17 实验](https://github.com/jnfkdsn/aicompiler/tree/main/llvm-mlir/17-matmul-attention)。
