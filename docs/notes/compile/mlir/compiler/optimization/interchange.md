# 循环交换、并行化与归约次序

遍历同一个矩阵，既可以先逐行，也可以先逐列。结果是否相同取决于各次计算之间的依赖；性能是否相同取决于布局、复用和目标执行方式。这两项判断需要分开完成。

本章先交换一个独立的逐元素计算，再用跨行递推展示失败条件，最后把顺序要求推广到并行归约和浮点运算。

## 1. 遍历顺序与数据布局

对前篇的 `Y[i,j]=2*(X[i,j]+1)`，原顺序是：

```text
for i in 0..M:
  for j in 0..N:
    计算 Y[i,j]
```

交换为先 j 后 i，仍对每个坐标做同一计算。由于不同结果彼此独立，且输入和输出契约排除了影响读取的覆盖，交换可以保留结果。

但若 X/Y 都是行主序，原顺序的内循环访问相邻元素；交换后，内循环相邻两次访问的地址相差 N 个元素。它可能影响缓存行使用、预取和向量化。交换改变的是访问顺序，没有把矩阵转置成另一种存储布局。

## 2. Linalg 中的迭代维置换

Linalg 把迭代坐标与 operand 坐标分开。原先使用：

```text
迭代坐标 (d0,d1)，范围 (M,N)
输入/输出 map：(d0,d1) -> (d0,d1)
```

交换两个 iterator 后，新的迭代顺序以列为外层、行为内层，因此要同时更新访问映射：

```text
新迭代坐标 (d0,d1)，对应原来的 (j,i)
输入/输出 map：(d0,d1) -> (d1,d0)
```

在非方阵 5×7 上，新的迭代范围相应是 7×5，而被访问的 tensor 仍是 5×7。配套 Transform 调度调用 structured interchange 后，实际 generic 的两个 maps 都变为 `(d0,d1)->(d1,d0)`，最终输出仍按原坐标存放。

只交换循环嵌套、却忘记解释变量和 map 的对应，会把“改变顺序”误写成“改变计算”。非方阵和按坐标变化的输入是发现这类错误的有效测试。

## 3. 依赖方向限制交换

对比[Affine 依赖章](../../dialects/affine/loops_analysis)的递推：

```text
A[i,j] = A[i-1,j+1] + 1
```

从产生 A[is,js] 的迭代到读取它的迭代，距离为 `(1,-1)`。原先先看 i 的顺序保证前一行先完成；交换后先看 j，读取可能发生在所需写入之前。

真实分析输出为 `swap legal: 0`。本机对照则更直观：初始 `A[i,j]=100*i+j` 时，原顺序的 `A[2,0]=4`，手工错误交换后变成 102。两份输入都能通过结构验证，差别来自依赖被破坏。

一般地，交换要维护所有相关依赖在新执行顺序中的方向。单个方向分量出现负数并不必然非法，关键在于新词典序中第一个决定先后的非零分量；同时还要考虑域、条件和多个访问之间的所有约束。

## 4. 可交换与可并行的区别

某个循环可以交换，并不表示任意一维都可以无条件并行。并行执行需要独立结果，或明确可实现的归约/同步协议。

矩阵乘法中，i/j 标识不同输出，k 为同一个输出逐步累加贡献。若输入输出之间满足相应独立性，调整 i/j 的遍历通常不会改变每个输出内部 k 的顺序；将 k 分给多个线程却会让它们同时更新同一位置，需要部分和、原子或其他归约机制。

同样，前面的跨行递推外层 i 有依赖，内层 j 可以在一行内并行。把所有 affine.for 统一换成 parallel，不会自动产生缺失的行间同步。

Linalg 的 parallel/reduction 标记描述计算结构，具体线程映射仍需下游实现，并且依赖语义和 buffer 别名约束必须符合声明。

## 5. 归约次序与浮点误差

普通整数在相同位宽、无额外溢出契约的模运算下，与浮点加法具有不同的重排性质。浮点会在每次运算后舍入，因此结合次序可能影响结果。

例如 f32 中考虑 `a=16777216,b=1,c=-16777216`：

```text
(a+b)+c：a+b 舍入回 16777216，最后得 0
 a+(b+c)：b+c 可表示为 -16777215，最后得 1
```

并行 reduction tree、分块部分和、向量归约，都可能改变括号对应的加法次序。希望采用这些实现时，需要核对源操作是否允许相应顺序、是否有 reassociation 契约，以及任务容许的误差。

某些结构化 reduction 本身允许由调度选择次序，某些顺序循环则明确表达了 carried value 的逐步递推；不能脱离所用操作语义，把全部“求和”都当成同一个可自由重排的对象。即使变换在源契约下合法，也仍需要为算法任务检查数值是否可接受。

## 6. Pipeline 中的决策

一个完整的交换决策可以沿三个层次完成：先由访问与依赖判断允许哪些排列，再由布局和复用提出可能更好的顺序，最后由实际目标与测量筛选方案。

当前逐元素例子通过真实 interchange 得到另一种合法顺序，并在 5×7、7×5、单行和空域等输入上与参考核对。递推反例则由真实依赖查询和数值差异共同说明不合法。它们都没有给出速度结论。

后续 Vector 会使某些连续内层迭代组合为向量，目标映射会把某些迭代交给线程。此时，循环顺序、向量元素组织和物理布局必须放在同一条访问路径中解释，而不能各自独立选择。

## 阅读自查

1. Linalg iterator 交换后，为什么需要相应修改 indexing maps，却不要求转置 tensor 的物理存储？
2. 递推中 `[2,0]` 从 4 变成 102，究竟提前了哪一次读取？
3. k 维可以分块，为什么仍不能让多个线程无协议地更新同一个 C 元素？
4. 数值测试“误差在容忍内”能否替代对源操作变换契约的检查？
