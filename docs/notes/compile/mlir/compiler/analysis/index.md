# 分析事实与优化合法性

一个优化规则提出“把计算提前”“复用已有结果”或“删除无用操作”，分析为它提供判断所需的事实。首先要知道值在哪里可用，再确认内存与执行条件是否允许变化；IR 改动后，还要维护这些结论的有效性。

```text
希望实施的变换
    ↓
需要哪些事实：可用的值、可能的地址、可达路径与数值范围
    ↓
分析计算事实 → 变换检查条件 → 修改 IR
    ↓
保留仍有效的分析，失效并重算已过期的分析
```

## 阅读主线

已有 Pass、SSA、效果和 MemRef 基础后，可按下列顺序阅读。传统编译器算法概览继续由[Dataflow 与 Pass Pipeline](../../../traditional/dataflow_pass)承担，本模块解释这些判断怎样作用于 MLIR 的嵌套 IR 和可扩展操作。

| 顺序 | 章节 | 连续推进的判断 |
|---|---|---|
| 1 | [支配、活跃性与操作移动](./dominance_liveness) | 分支中的结果能否移出，输入在哪里可用，最后一次使用与 Buffer 释放为何不同；补后支配与调用图边界 |
| 2 | [别名、效果与内存依赖](./alias_effects) | 两次 load 中间写入后结果是否仍相同；区分底层来源与精确访问关系 |
| 3 | [分析结果的缓存与失效](./caching) | 同一个函数从 9 个操作变成 10 个，缓存怎样复用、过期和重算 |
| 4 | [数据流事实的传播与收敛](./dataflow) | 从 3+4 沿两个分支推出 7，再进入 join、可达性、工作列表和整数范围 |
| 5 | [CSE、DCE 与 LICM 的合法性](./legality) | 合并、删除和外提分别改变什么；以零次循环与别名反例核对条件 |

五篇主线与配套查询、编译和数值观察已提供。分析实现能力仍需通过自己改动条件、解释结果来建立；作者示例通过不等于读者已完成独立实践。

## 与后续优化的连接

先读主例推演，再按需要查看 API 与实现依据。无需先自己实现通用别名分析或求解器，才允许进入算法优化。后续 tiling、fusion 和并行化会把这里的依赖与执行条件推广到迭代域、tile 和线程之间；更强的分析按所需证明逐步引入。

范围见[覆盖表 A01—A04](../../coverage)，全局顺序见[章节目录](../../chapter_plan)。可选的[分析实验](https://github.com/jnfkdsn/aicompiler/tree/main/llvm-mlir/12-analysis)提供实际查询、前后 IR 和两个有限练习。
