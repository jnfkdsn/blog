# 学习路线

理解 AI 编译与执行，需要把模型中的计算、编译器中的表示、硬件上的算子和运行时的组织联系起来。知识库按这些对象归档，学习时则围绕一个具体程序穿过它们，不必按文件夹顺序逐页读完。

## 四个领域如何连接

以矩阵乘法、bias 和激活为例：模型描述希望得到的结果，编译器决定保留哪些操作、能否融合，以及调用已有实现还是生成代码；算子实现安排分块、访存和并行；运行时管理输入、存储和调用。在推理服务中，请求批次与序列长度又决定了这段计算实际面对的形状。

| 当前需要解释的事情 | 对应入口 |
|---|---|
| 函数、对象、模板和工程怎样组成程序 | [C++ 工程基础](./cpp/) |
| 计算如何表示、变换和生成执行产物 | [编译器](./compile/) |
| 一个计算如何映射到 GPU/NPU 资源 | [算子编程与优化](./kernels/) |
| 模型怎样逐步执行，请求如何驱动计算 | [模型与推理系统](./inference/) |

## 建立编译全链路认识

有传统编译基础时，可先从 [MLIR 学习路径](./compile/mlir/learning_path)选择必要的 IR 与变换内容。能够解释一个小程序和一次变换后，就可以穿插具体编译系统，不必等全部 MLIR 扩展学完。

接着分别阅读 [TVM 总览](./compile/tvm/01_execution)与 [PyTorch Compiler 总览](./compile/pytorch-compiler/01_execution)，沿各自课程追踪模型、IR、实现选择、产物与执行。第一轮以推理为主，再用 [PyTorch 训练章节](./compile/pytorch-compiler/08_training)理解反向图带来的变化。

两套系统之后，借助[系统对照](./compile/compiler_comparison)选择深入点：图优化与动态形状、算子编译与目标后端、内存与运行时都可以成为后续主线。

## 深入算子与目标编译

从 [CUDA](./kernels/cuda/)或 [Ascend C](./kernels/ascend-c/)了解目标硬件的计算、存储和同步，再用 Reduce、Softmax、Matmul 等小算子建立正确性与性能判断。可以只选择当前硬件可验证的一条路线。

进入 [Triton](./compile/triton/)时，先理解块级程序表达，再跟踪一个加法 kernel 的编译路径。随后将任务扩大到归约或矩阵乘法，分析布局、并行映射与代码生成；Triton-Ascend 按自己的目标路径单独验证。

## 连接模型与推理运行时

[模型结构](./inference/model_architecture)解释算子在计算中的位置；[FlashAttention](./kernels/algorithms/flash_attention)连接算法与访存；[nano-vLLM](./inference/nanovllm)提供推理引擎的源码阅读入口。先围绕模型计算与一次请求建立认识，再按任务深入量化、批处理和缓存管理。

当前推理笔记仍在扩展，已有内容和待补范围集中写在[推理系统首页](./inference/)。该方向可以与编译器学习交替进行，不成为开始编译实验的新前置关卡。

## 阅读与实践的深度

每轮选择一个有限产物：解释一次表示变化、修改一条规则、实现一个算子，或追踪一次调用。先写出预期，再通过 IR、测试或测量检查结果。通读文档、运行参考程序与独立实现是不同的学习成果。

长期深化目标见[编译器能力与项目](./compile/capabilities)。各模块首页维护自己的篇章顺序；个人阅读进度在工作区记录，不写入公开教程的“下一步”安排。
